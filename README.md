# 2024 H 题自动行驶小车

在原 MSPM0G3507 单电机 PID 工程上改造，硬件为双 JGB37-520、TB6612、8 路数字灰度、MPU6050。保留 OLED 与串口显示，取消舵机功能。

代码已通过 TI SysConfig、TI Arm Clang 编译链接和主机控制逻辑测试。尚未连接实车测试；速度环参数、轮径、脉冲数、灰度极性及转弯衔接均需按下面步骤标定。

## 从哪里开始读代码

先读 `CODE_GUIDE.md`，再按 `empty.c → car.c → drive.c → pid.c` 的顺序看。`empty.c` 的 10ms 中断只有五个主要步骤；`car.c` 用路线表和直行、转向、循弧线三个函数描述正常行驶，运行保护集中在 `check_running_conditions`。速度 PID 只提供本项目需要的正向 PWM 接口。

## 对应赛题

| 按键选择 | 路线 | 目标 |
| --- | --- | --- |
| M1 | A → B 停车 | 不超过 15 秒 |
| M2 | A → B → C → D → A 停车 | 不超过 30 秒 |
| M3 | A → C → B → D → A 停车 | 不超过 40 秒 |
| M4 | M3 路线连续 4 圈后停车 | 在稳定完成的前提下提速 |

赛题只有 B–C 和 D–A 两段黑色半圆，没有直线或交叉黑线，也没有额外的顶点标记。程序按 AB=1000 mm、AD=800 mm、圆弧半径=400 mm 建模。斜线长约 1280.625 mm，斜线与水平方向夹角约 38.660°。

直线/斜线采用“双编码器里程 + MPU6050 航向与横向偏差反馈”；圆弧采用“已知曲率前馈 + 灰度位置 PD”。顶点根据里程、转角与当前路段判定，启动及每经过顶点均给出一次声光提示。没有使用额外场地标记、摄像头或遥控。

交叉路线在顶点附近用小半径前进转弯接入下一路段，两轮目标速度均非负，禁止原地反转；速度环负误差仅降低 PWM 或制动。顶点判定依赖标定后的里程和陀螺仪角度，不是直接识别 A/B/C/D。必须在实车确认转向全过程车身投影覆盖黑弧，以及顶点提示时车身覆盖对应顶点。整车外廓仍需满足 250 × 150 × 150 mm。

**灰度从车头朝前看，从左到右对应 S0～S7：**

| 灰度信号 | S0 | S1 | S2 | S3 | S4 | S5 | S6 | S7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| MCU 引脚 | PB0 | PB1 | PB4 | PB5 | PB8 | PB9 | PB10 | PB11 |

TB6612 的 AO1/AO2 接左电机，BO1/BO2 接右电机；VCC 逻辑电源用 3.3 V，VM 接匹配电机额定电压的电机电源，各模块共地。MPU6050 的 I²C 信号上拉到 3.3 V，AD0 接低电平默认地址 0x68。两组 I²C 总线都需要上拉电阻，模块已有上拉时检查其上拉电源。编码器、灰度的 MCU 侧信号统一为 3.3 V，输出为 5 V 时先做电平转换。蜂鸣器使用有源驱动模块或三极管驱动级，PA24 为控制信号。

TB6612 能否驱动这两台电机，需要按你手上 JGB37-520 的电压及负载/堵转电流核对。型号名不包含这些参数。东芝数据表列出的 1.2 A 和 3.2 A 分别涉及平均/额定与受时间约束的峰值条件，不能把 3.2 A 当成每路持续驱动能力；PWM 限幅也不是电流限流。[TB6612 原厂数据表](https://toshiba.semicon-storage.com/info/TB6612FNG_datasheet_en_20141001.pdf?did=10660&prodName=TB6612FNG)。

## 必须先填的参数

所有实车参数集中在 `app_config.h`。以下四项默认是 0，表示未标定，按启动键会显示 `CFG` 并保持电机关闭。此时仍能查看编码器、灰度及 IMU 数据。

```c
#define CAR_WHEEL_DIAMETER_MM           0.0f
#define CAR_LEFT_COUNTS_PER_WHEEL_REV   0.0f
#define CAR_RIGHT_COUNTS_PER_WHEEL_REV  0.0f
#define CAR_WHEEL_TRACK_MM              0.0f
```

- **轮径**：填轮胎实际滚动直径，单位 mm。可用推行多圈的距离反算有效直径。
- **每圈计数**：填减速箱输出轴/车轮转一整圈的计数。本程序只数编码器 A 相上升沿（1 倍频），不是四倍频，也不是电机转子轴转一圈的计数。
- **轮距**：填左右轮接地中心的横向间距，单位 mm；不是前后轴距。
- **单位换算**：每计数距离 = π × 轮径 / 每圈计数；速度环目标 = 轮速(mm/s) × 0.01 / 每计数距离。

不预填一个猜测的 JGB37-520 减速比或脉冲数，因为不同批次/配置差异较大。

## 上车调试顺序

1. **接线后先静止上电。** MPU6050 自动等待稳定并采样约 3 秒做零偏标定。校准时不要动小车。出现 `IMU` 时检查接线、地址、供电和校准期间是否移动，再复位。
2. **手动车轮检查编码器。** 暂不启动路线，记录串口 `total`，向前转左右轮各 10 圈，用计数差除以 10 得每圈计数。车身前进时两个计数都必须增加；反向则调整对应 `ENCODER_*_SIGN`，不要把反馈取绝对值。
3. **测轮径与轮距**，填写四项几何参数，重新编译。随后先架空车轮，检查 `MOTOR_*_FORWARD_SIGN`。默认假设两电机镜像安装；若物理方向不符，改宏或交换对应电机的两根电源线，编码器方向另行验证。
4. **检查 MPU6050 方向。** 传感器 Z 轴应垂直地面，手动左转时 OLED 的 Y/串口 `yaw10` 增加；相反则改 `IMU_YAW_SIGN`。MPU6050 没有磁力计，yaw 是启动后的相对积分角度，每次启动路线都会清零。存在随时间、振动和温度变化的漂移，长时间测试前应重新静止上电。
5. **检查灰度。** OLED 的 `Gxx` 和串口 `gray` 为“1=黑”的掩码，bit0 对应最左探头。默认 DO 黑=低；实测相反则改 `LINE_BLACK_LEVEL`。白底应为 00，中间探头在黑线上通常为 08/10/18 等。FF、多条分离黑区、超过 5 路同时黑均作为无效线位置处理，检查阈值、安装高度和探头顺序。
6. **先调双轮速度环。** 降低直线/弧线速度和 PWM 上限，先架空确认两轮正转和正计数；再从 M1 测试。`SPEED_PID_KP/KI/KD` 的反馈单位是计数/10 ms，`KI` 已含离散采样周期，不能直接搬用以 rpm 或每秒为单位的参数。当前值只是起调值。
7. **用 M1 标定距离与停车。** 调整有效轮径或每圈计数，使里程对应实测 1000 mm。实测刹车后多走多少 mm，可填入 `CAR_STOP_LEAD_MM`；同样的提前量也用于最终圆弧停车。经过中间顶点时不使用停车提前量。
8. **依次测试 M2、M3、M4。** 调整灰度排距轮轴的 `CAR_SENSOR_FORWARD_MM`（默认 50 mm）、巡线 PD、航向参数及速度。当前小半径转向约为轮距的 0.55 倍；在斜线与圆弧衔接处确认前置灰度排能接到弧线，车身始终覆盖黑弧。稳定完成一圈后，再验证四圈累计误差并提速。

初始摆放：M1/M2 在 A 点朝 B；M3/M4 在 A 点朝 C。车轮轴线中心作为程序的里程参考点，初始摆放和停车标定需保持一致。蜂鸣器对应的是软件判定的顶点，必须在实物确认提示时车身投影覆盖顶点。

## 操作与故障码

- 上电不自动行驶。**KEY2** 在待机/完成/故障状态循环选择 M1～M4；**KEY1** 启动当前项目。
- 行驶中 **KEY2** 紧急停车，立即清除 PID 和速度斜坡并制动。正式比赛应全程自动行驶，这个功能用于调试。
- 启动 A 点、经过各顶点及最终停车时，LED0 与蜂鸣器同步提示约 120 ms；行驶时 LED1 点亮。故障时周期声光提示。
- 停车立即短路制动约 300 ms，随后 STBY 关闭。不会用电机反转停车。
- 串口只输出调试信息，没有遥控或赛中参数修改入口。

| 代码 | 含义与处理 |
| --- | --- |
| CFG | 几何参数未填写或不合理，检查四项必填参数 |
| IMU | 初始化、静止校准或运行期间 I²C 读取失败；检查后复位 |
| LINE | 弧线未接到黑线，或中途持续失线；检查灰度与衔接位置 |
| DIR | 持续检测到负向计数；核对电机和编码器方向 |
| STALL | 某轮有速度目标但持续约 1.2 秒无计数；检查卡滞、供电、编码器、PWM/PID |
| TIME | 任务或前进转向超时 |
| DIST | 弧段里程过长，或直线横向偏差/里程异常 |

弧线中途已接线后，持续失线约 150 ms 停车；接入弧线最多允许约 800 ms 寻线。前置灰度排会先于轮轴离开弧线终点，程序仅在“已循线、里程接近半圈、角度接近终点”时允许按曲率补完末段。M1/M2/M3 的软件最终超时保护分别为 30/60/80 秒；赛题正常目标仍是 15/30/40 秒。M4 设置了 240 秒调试超时。

## 构建与验证

在 CCS 中对该项目执行 **Clean/Rebuild**，让 SysConfig 重新生成 `Debug` 里的配置，不能继续使用旧生成文件。新增 C 文件在项目根目录，`.cproject` 已排除 `.build`、`tests`、`tools`，避免测试的 main 被编入固件。`makefile.defs` 为 CCS 链接设置 2048 字节栈。

也可以在项目根目录用本机已安装的工具执行：

```powershell
./tools/build.ps1
./tools/test.ps1
```

构建脚本默认使用 MSPM0 SDK 2.11.00.07、SysConfig 1.26.2、TI Arm Clang 4.0.4.LTS；安装位置不同时可用脚本参数 `-Sdk`、`-SysConfig`、`-Compiler` 覆盖。输出为 `.build/h2024_car.out` 和 `.build/h2024_car.bin`。**当前输出使用未标定的默认配置，不能直接作为上赛道固件；填好参数后重新构建。**

测试脚本使用本机 MinGW GCC，可通过 `-Compiler` 指定另一个 GCC。测试包括四种路线的顶点顺序、四圈停止、非负轮速、轮速/PWM 限幅、PID 饱和、立即停车，以及失线、IMU 通信失败、反向计数、无脉冲和超时。场地模型只生成两段半圆黑线，并检查理想执行器与带速度斜坡/60 ms 响应延迟两种情况。日志在 `.build/control-tests.log`。

这些测试验证软件逻辑，不代表实车的停车精度、圈速或比赛达标。地面打滑、左右轮直径差、传感器安装偏差、惯性和陀螺仪漂移仍须实测。
